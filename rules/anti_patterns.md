# 反模式清单（Anti-Patterns）

> 生成 HTML 演示文稿时的常见错误用法与正确做法对照。命中的行为一律纠正。

## 1. 凭记忆编配色（最严重）

- **症状**：不读 L2 风格资产，直接凭印象写颜色（如"赛博朋克就用青色吧"）。
- **危害**：风格还原度崩塌，49 风格资产形同虚设，审核必 BLOCK-风格还原度。
- **正确**：生成前必读 `assets/body/{编号}_{class}.md` 的「配色 Token」，逐色抄用。

## 2. 跳过大纲直接生成

- **症状**：用户给个主题，不产大纲草案就直接糊一版 HTML。
- **危害**：页面结构、页数、要点没和用户对齐，返工率高。
- **正确**：先出「演示大纲（草案）」→ 用户确认/调整 → 再选型 → 再生成。

## 3. 一步到位输出最终大 HTML

- **症状**：不出中间产物（大纲/选型卡），直接甩最终文件。
- **危害**：用户无法中途纠偏，方向错了全盘返工。
- **正确**：大纲卡、选型卡、状态卡等中间产物逐级呈现，阶段门控。

## 4. 缺翻页 / 进度 / 圆点跳页

- **症状**：生成静态长页 HTML，没有左右翻页、底部页码/进度条、圆点跳页。
- **危害**：不像"演示文稿"，投屏体验差，审核 BLOCK-翻页进度。
- **正确**：三通道翻页（键盘/箭头/触屏）+ 底部「N / M」+ 进度条 + 圆点跳页，缺一不可。

## 5. 编造数据与事实

- **症状**：用户没给数据，自己编"增长 35%""融资 5000 万"。
- **危害**：误导受众，交付即事故。
- **正确**：只填用户事实，缺口用 `【待补充：XXX】` 占位。

## 6. 风格混搭不标注来源

- **症状**：混用了多套风格组件，却不说明各组件来自哪套风格。
- **危害**：交付说不清设计依据，可维护性差。
- **正确**：混搭时在交付说明中标注"主风格 A23 + 借用 A46 卡片"。

## 7. 单文件无限膨胀 / 不渐进加载

- **症状**：把 49 份资产一次性灌进上下文，或把整份资产塞进一个 HTML。
- **危害**：上下文爆炸、token 浪费、生成缓慢。
- **正确**：三级加载（L0→L1→L2），单会话只读 1 份 L2；HTML 内只注入当前风格 token。

## 8. 忽视响应式

- **症状**：只做桌面版式，窄屏内容溢出/不可读。
- **危害**：手机/平板打开体验崩坏，审核 BLOCK-响应式。
- **正确**：1024/640 双断点，网格 auto-fit，字号 clamp()，窄屏单列。
