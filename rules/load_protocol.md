# 检索加载协议（三级 L0/L1/L2）

> 核心机制：**L0/L1 随系统提示词常驻；L2 风格正文按需读取唯一 1 份。**

## 平台兼容说明
- **知识库检索**：平台支持知识库时，L2 正文通过知识库检索命中；不支持时由 LLM 按本协议声明的相对路径（如 `assets/body/A23_cy.md`）直接读取文件。
- **无外部依赖**：本协议不依赖 CLI 工具或外部 API，纯 LLM 对话即可执行。

## 目标
LLM 如何从 49 份风格资产中，用最少步数、最小 token 定位并读入"恰好该用的 1 份"，且不因记忆偏差选错风格。

## 三级加载总表

| 级 | 加载时机 | 读取对象 | 产出 | 体量 |
| --- | --- | --- | --- | --- |
| L0·选型 | S3 起通读 | `assets/catalog/catalog_l0.md` | 明暗硬过滤 → 候选族 ≤3 | 约 2k 字 |
| L1·按族 | S3 确认候选族后 | `assets/index/{族}.md`（≤3 个） | 精确到唯一风格 + 正文路径 | 约 1k 字/族 |
| L2·正文 | S4 确认后 | `assets/body/{编号}_{class}.md`（仅 1 份） | 完整创作载荷（配色/字体/特效/组件/版式） | 约 1.5k 字 |

## 定位规则（机器约束 + LLM 判定双层）

1. **L0 快速过滤**（按 `catalog_l0.md` 的 7 族总览）：
   - 先按**明暗调性**硬过滤（投影/打印→浅色族；屏幕/沉浸→深色族）。
   - 再用业务场景关键词匹配族"适用方向"，锁定 ≤3 候选族。
   - 跨族场景（如"科技+高级感"既可能玻璃光影也可能科技霓虹）同时取相关候选族。
2. **L1 精定位**：读取候选族索引（≤3 份），用「场景关键词 × 调性 × 品牌气质」加权 → 定唯一风格。
   - **冲突不合并**：族内 ≥2 个风格同时命中时，禁止自行合并或二选一，回选型建议卡让用户挑并给出判别语。
3. **L2 声明门控**：读取正文前，回复须先声明 `[资产引用] {编号}→{风格名}`；无此声明的生成视为违规穿越（产物门控）。
4. **缺档兜底**：族索引给了路径但正文缺失 → 自动降级 `assets/common/skeleton_base.md` 并明示。
5. **跨族相似对照**：候选同时落在两族时，两族索引都读，用对照行给出判别。

## 族索引行格式（一行一风格）
```text
风格|名称|调性|场景关键词|强调色|一句话|→assets/body/{编号}_{class}.md
```

## 规则文件加载说明

| 规则文件 | 加载时机 | 说明 |
| --- | --- | --- |
| `assets/common/palette_guide.md` | S5 生成时常驻 | 配色变量约定 + 无障碍对比度 |
| `assets/common/slide_patterns.md` | S5 生成时常驻 | 五种页面模式 |
| `rules/html_guide.md` | S5 生成时常驻 | HTML 技术规范 |
| `rules/quality_gate.md` | S6 审核时按需 | 五维审核与阻断判定 |
| `rules/anti_patterns.md` | S5/S6 按需 | 反模式清单（凭记忆编配色/跳大纲/缺翻页等） |
| `assets/common/skeleton_base.md` | 缺档兜底时按需 | 通用骨架 |

## 运行时动作铁律

1. 生成前必须先读到 L2 正文，以其中的配色 token、字体、形状特效、组件样式作为生成约束。
2. **禁止仅凭模型训练记忆编配色**；正文未命中 → 走通用骨架降级并明示。
3. 索引/规则文件只读不改；正文只读不缓存。

## 会话预算

- 单会话默认只读 1 份 L2 正文（"从零生成 + 修订续写"最多 2 份）；多风格对比 L1 ≤3 份、L2 ≤2 份。
- S6 审核复用同一份 L2 正文做基准，不重复读取。
